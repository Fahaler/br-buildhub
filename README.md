# BR BuildHub

Блокнот заказов на постройки в Brick Rigs: список заказов, статусы, приоритеты, цены и фото.
Смотреть заказы может кто угодно, создавать и менять — только админы.

**Стек:** Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Supabase (база, вход, хранилище фото) · Vercel.

## Запуск локально

```bash
npm install
cp .env.example .env.local   # и вписать свои значения из Supabase
npm run dev                  # http://localhost:3000
```

## Структура

Весь блокнот — одна страница-«пульт»: слева фильтры, в центре список, справа карточка заказа или редактор.
На телефоне список и карточка открываются по очереди.

| Путь | Что там |
| --- | --- |
| `src/app/page.tsx` | Главная: загружает заказы на сервере и отдаёт их пульту |
| `src/components/notebook/Notebook.tsx` | Пульт: фильтры, поиск, список, горячие клавиши, быстрая смена статуса и оплаты |
| `src/components/notebook/OrderDetail.tsx` | Карточка заказа: фото, цена, оплата и предоплата, «Продано», дедлайн, лимит бриков, ТЗ-чек-лист |
| `src/components/notebook/ClientDialog.tsx` | Карточка клиента: все заказы и покупки по нику, сколько всего, получено и долг |
| `src/components/notebook/OrderEditor.tsx` | Создание и правка заказа (только админы) |
| `src/components/notebook/StatsView.tsx` | Статистика: периоды, деньги и долги, столбики по месяцам, статусы, продажи, топ клиентов |
| `src/components/notebook/PhotoEditor.tsx` | До 8 фото: перетаскивание, Ctrl+V, порядок, обложка |
| `src/app/login` | Вход |
| `src/proxy.ts` | Обновляет сессию входа |
| `src/lib/orders.ts` | Статусы, оплата, приоритеты, даты, дедлайны, разбор цены, деньги, периоды, клиенты |
| `src/lib/checklist.ts` | Чек-лист из ТЗ: разбор пунктов, прогресс, отметка «✓» |
| `src/lib/saveOrder.ts` | Сохранение, быстрые правки и удаление заказов |
| `src/lib/images.ts` | Сжатие фото в WebP и работа с хранилищем |

Старые адреса `/new-order` и `/orders/<id>` перенаправляются на главную (`/?new=1`, `/?id=<id>`).

## Поля заказа

| Поле | Колонка | Примечание |
| --- | --- | --- |
| Что строим | `title` | обязательно |
| Для кого | `kind` | заказ (клиенту) / продажа (строим сами на продажу — не входит в статистику, вместо цены и оплаты — «Цена продажи») |
| Ник клиента | `client_nick` | до 64 символов, можно пусто; при вводе подсказываются знакомые ники. Нажмите на ник в карточке — откроется карточка клиента |
| ТЗ | `description` | ссылки становятся кликабельными, строки с «•», «-», «1.» — чек-листом (см. ниже) |
| Лимит бриков | `brick_limit` | целое число, понимает «2 300» |
| Цена | `cost` | см. ниже |
| Статус | `status` | в очереди / в процессе / готов / отмена |
| Приоритет | `priority` | низкий / обычный / высокий («Срочно») |
| Оплата | `payment` | нет / предоплата / оплачено |
| Сумма предоплаты | `prepaid_amount` | только при «Предоплате»; правится прямо в карточке |
| Продано | `sold_at`, `sold_price` | только для вещей на продажу: дата продажи и за сколько (пусто — по цене продажи) |
| Дата заказа | `ordered_at` | по умолчанию сегодня; для старых заказов ставится вручную. По ней считаются номера и очередь |
| Дедлайн | `deadline` | пусто — без дедлайна |
| Фото | `images` | до 8 ссылок по порядку, первое — обложка |

## Горячие клавиши

`↑`/`↓` (или `J`/`K`) — выбор заказа, `←`/`→` — фото, `/` — поиск, `Esc` — закрыть.
`S` — статистика. Для админов: `1`–`4` — статус, `E` — изменить, `N` — новый заказ, `Ctrl+Enter` — сохранить.

## Настройка Supabase

1. `supabase/001-security.sql` — таблица админов и правила доступа (RLS). Перед запуском впишите почты админов.
2. `supabase/002-storage-limits.sql` — лимит 10 МБ и только картинки в бакете `order-images`.
3. `supabase/003-notebook-fields.sql` — новые поля (ник, дата заказа, дедлайн, оплата, до 8 фото).
   **Запустите до деплоя этой версии.** Старые фото переносятся в `images`, даты из строк «*От: 05.11.26» — в `ordered_at`.
4. `supabase/004-for-sale.sql` — поле `kind`: заказ или вещь на продажу. Все старые записи становятся заказами.
   **Запустите до деплоя этой версии.**
5. `supabase/005-money-sales.sql` — сумма предоплаты, дата и цена продажи, лимит бриков (`prepaid_amount`, `sold_at`, `sold_price`, `brick_limit`).
   **Запустите до деплоя этой версии.** Старые записи не меняются — новые поля у них просто пустые.

## Статистика

Вкладка «Статистика» (или `?view=stats`, клавиша `S`):

- **Период**: «Всё время», «Этот год», «Этот месяц», «Прошлый месяц» или любой месяц — нажатием на столбик. Заказы попадают в период по дате заказа, продажи — по дате продажи.
- **Суммы**: всех заказов, готовых, количество, разбивка по статусам.
- **Деньги**: «Получено» (оплаченные целиком + суммы предоплат), «Осталось получить», «Долги по готовым» со списком таких заказов. Отменённые не считаются.
- **По месяцам**: столбики за последние 12 месяцев — сумма заказов (без отменённых) и сколько из неё готово.
- **Продажи**: сколько вещей сейчас в продаже и на какую сумму, сколько продано за период.
- **Топ клиентов**: пятеро с самой большой суммой заказов и покупок; нажатие открывает карточку клиента.

Заказы без цены входят в количество, но не в суммы.

## Чек-лист ТЗ

Строки ТЗ, которые начинаются с «•», «-», «*» или «1.», показываются в карточке пунктами с галочками — админ отмечает их нажатием.
Отмеченный пункт хранится в тексте как та же строка с «✓ » в начале («✓ • рабочие двери»), поэтому его можно поправить и в обычном редакторе.
В списке у активных заказов виден прогресс, например «3/5».

## Вещи на продажу

Кнопка «Продано» в карточке: цена (по умолчанию — цена продажи), покупатель и дата (по умолчанию — сегодня).
Если вещь ещё строилась, она заодно становится «Готово». «Вернуть в продажу» снимает отметку.
Дату и цену продажи можно поправить и в форме.

Настоящая защита данных — правила RLS в базе.

## Цена

Поле цены понимает `1500`, `1 500`, `1.500`, `1,500`, `1 500 ₽` (всё это 1500), а также `99,90`, `1.500,50` и `1,500.50`.
Пустое поле означает «цена не указана». Разбор цены — `parseCost` в `src/lib/orders.ts`.
